# Make Plan — 任务拆解与计划

## 适用场景

- 任务需要多步拆解、步骤之间有依赖关系、涉及多个命令/模块/系统
- 用户要求「先给计划再执行」
- 与 /Plan 执行模式互补：/Plan 由 LLM 自动分解 3-7 步独立执行；本技能产出计划后由 Agent 逐步执行并向用户汇报

## 执行步骤

### 1. 分析任务
- 理解用户最终目标
- `self.tools [ns]` 确认有哪些可用命令（按命名空间查）
- `agent.memory` 看长期记忆是否有相关经验；`agent.memory.read <条目>` 读具体内容

### 2. 制定计划
向用户输出：

```
## 执行计划：{任务简述}

| 步骤 | 操作 | 预期结果 | 验证方式 |
|------|------|---------|---------|
| 1 | ... | ... | ... |
| 2 | ... | ... | ... |

预计共 N 步。确认后开始执行。
```

### 3. 逐步执行
- 用户确认后按顺序执行
- 每步执行完汇报结果
- 步骤失败时分析原因，调整计划后继续

### 4. 完成汇报
- 完成了哪些步骤 / 最终结果 / 是否有遗留问题

## 注意事项

- **只要计划，不要代执行**：先用 `self.tools` 了解自己有什么能力，再制定计划
- **步骤必须具体**：不能用抽象建议代替可执行步骤
- **包含验证方式**：每步说明完成标志
- 不适合：单命令可完成的事；缺少关键信息（先问用户）；任务目标没理解清楚（先澄清）

## 进化目标

- 目标: 覆盖多步任务的全周期——从拆解到执行到复盘汇报
- 稳定锚点: 计划表格格式（步骤/操作/预期/验证）与「确认后执行」流程
- 收敛原则: 升级朝计划质量收敛；新场景需求开新技能，不污染本技能
