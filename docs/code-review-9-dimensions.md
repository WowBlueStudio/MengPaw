# 九维代码审查法

> **通用版(2026-08-08 抽象)**: 从 MengPaw v0.17.1 两轮全量审查(102 项发现全修复)沉淀, 原版曾于 v0.24.0 清理, 现恢复并抽象为项目无关的代码质量审查方法论。
> 适用于**任何"代码写得好不好"**的审查: 新功能 PR、大文件重构、模块交接、技术债盘点。
> 互补关系: 本方法问**代码质量**; 三层十二问(audit-methodology.md)问**功能闭环**; 金字塔彻查法(pyramid-investigation.md)问**现象为什么发生**。

## 核心信念

1. **机器门禁先行**: 编译 + 测试不通过, 直接判"需修改", 不进人工审查——门禁失败的代码谈质量没有意义。
2. **九维逐维过**: 每维一组检查要点 + 搜索模式, 用证据(file:line)说话, 不许"感觉没问题"。
3. **分级输出**: P0 阻塞 / P1 应修 / P2 可后续, 合并决策交给用户。

## 九维定义

| 维度 | 检查要点 | 搜索模式 |
|------|---------|---------|
| **1 可维护性** | 空 catch 吞错误; 单文件超行数红线(如 400); 硬编码是否该进 assets/资源; 手写序列化 | `catch (_: Exception) {}`、`catch (_: Throwable)` |
| **2 可读性** | 注释与行为一致且不过时; 命名与行为一致; 中英混杂; 文件超长 | 文件名 + 行数统计; 注释引用已删符号 |
| **3 可扩展性** | 新命令是否注册 metadata.commands; 生命周期 onInstall/onUninstall 是否真被调用; 关键词是否硬编码不可扩展 | `onInstall`/`onUninstall` 调用点; `register(` |
| **4 灵活性** | 硬编码 Agent 名/路径/模型; Android 依赖进入纯内核层; 无 DI 时依赖是否可注入 | `"MengPaw"`、`android.*` in kernel、`object` 单例 |
| **5 简洁性** | 重复代码; 重复构建配置/版本号/ProGuard 规则; 死代码(只赋值从不读取) | 版本号跨文件重复; 死变量(grep 赋值处无读取) |
| **6 可复用性** | 应抽取共享工具(如脱敏/路径消毒); 版本号冲突; 无 version catalog/convention 时是否该建 | 同逻辑多份拷贝; 版本硬编码散落 |
| **7 可测试性** | 核心逻辑有单元测试; 新插件/新模块有测试; 纯函数与副作用分离 | 模块 `src/test` 文件数; 复杂分支无测试 |
| **8 健壮性** | 线程安全(mutable 集合并发); CancellationException 是否被吞; IO 是否 try/catch; 路径穿越; renameTo 先删目标(Windows); OOM 上限 | `mutableMapOf`/`MutableList` 无锁; `catch (e: Exception)` 含 Cancellation; `renameTo(` |
| **9 兼容性** | 平台 API 移除项(如 API 33+); 语言/工具链版本一致(Java 17); Locale 明确; CRLF→LF | `capturePicture` 等废弃 API; `SimpleDateFormat(` 无 Locale; `.gitattributes` |

## 使用流程

1. **机器门禁**: 编译 + 全量测试, 失败 → 输出"需修改" + 失败详情, 结束
2. **定范围**: 本次审查的文件集/模块集(PR 变更集或整个模块)
3. **九维逐维过**: 每维按检查要点 + 搜索模式收集证据, 标注 file:line
4. **分级输出**:
   - P0 必修(崩溃/安全/数据丢失)
   - P1 应修(功能缺陷/体验/健壮性)
   - P2 可后续(代码质量/技术债)
5. **修复验证**: 修复后重跑门禁, 确认发现项闭环

## 输出格式

```
## 九维审查结论: <对象>

**门禁**: 编译 ✓ · 测试 ✓/✗ (N tests, F failures)

### P0 必修(阻塞)
- 问题 + 文件:line + 后果
### P1 应修
### P2 可后续
### 亮点(值得保留)
```

## 使用纪律

- 并行审查时按模块分区, 独立代理互不共享结论, 防互相污染
- 两个独立报告指向同一处才锁定根因; 同一层修两次没修好 → 立即换层(见金字塔彻查法)
- 每个发现附"为什么是问题"(后果), 不只列现象
- 修复项全部验证后才算闭环, 不留"标记了但没修"

## 实战案例(v0.17.1 原始审查, 102 项发现全修复)

> 审查日期 2026-07-28, 范围 ~100 Kotlin 文件 + 30 build 文件, 并行 3 路代理 + 人工复核。

### 代表性发现(按维)

| 维度 | 代表性发现 | 修复 |
|------|-----------|------|
| 1 可维护性 | 53 处空 catch 吞错误 | 全部加日志/ErrorCollector |
| 2 可读性 | requireActive 字段名与行为矛盾 | 修正命名 |
| 3 可扩展性 | onInstall/onUninstall 空白 try-catch 从未执行 | 改 suspend + 正确调用 |
| 4 灵活性 | AgentViewModel 硬编码 Agent 名 "MengPaw" | 参数化 |
| 5 简洁性 | 25 插件重复构建配置 + 重复版本号 | 根 subprojects 统一 |
| 6 可复用性 | 无 version catalog, 版本散落 25+ 文件 | 建议 libs.versions.toml |
| 7 可测试性 | 纯 JVM 模块不可测(全 Android library) | 内核拆分纯 JVM |
| 8 健壮性 | CancellationException 被吞破坏协程链 | 重新抛出 |
| 9 兼容性 | capturePicture() API 33+ 移除 Android 14 崩溃 | 改 View.draw() |

### 分级统计

P0 崩溃/安全 13 项(TOCTOU NPE、协程取消链断裂、无签名验证加载 JAR、可卸载任意 App、SSL 无条件 cancel、并发无同步等)全修复; P1 34 项、P2 41 项、P3 14 项全修复。完整清单见 git 历史 `19310f2^:docs/code-review-9-dimensions.md`。
