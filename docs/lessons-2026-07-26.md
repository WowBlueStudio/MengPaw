## 1. 提示词缓存（PromptEngine 三层缓存）

### 教训: 缓存检查顺序决定性能

原代码先读文件再检查缓存，即使命中也要做 3 次 `cachedRead`（查 mtime）——每次 LLM 调用都浪费 IO。

**修复**: 将提示词级缓存检查**前置**到文件读取之前。额外守卫 `docCache.isNotEmpty()` 确保被 `invalidateDocCache` 清空后不走缓存。

### 教训: 缓存失效用路径前缀，别用子串匹配

`docCache.keys.removeAll { agentName in it }` ——用 `String.contains` 做键过滤。如果 agentName 是 "Paw"，会误匹配 "MengPaw"。虽然当前所有 key 都以 `DataPaths.AGENTS` 开头，但这是个定时炸弹。

**修复**: 改为路径前缀匹配 `it.startsWith("${DataPaths.AGENTS}/$agentName/")`。

## 2. 插件跨模块依赖

### 教训: 插件不能 import APK 模块

`plugin-browser-mcp` 直接 import `com.mengpaw.browser.bridge.BrowserBridge` ——但 `mengpaw-browser` 是 APK 模块（`application`），不能作为 library 依赖。编译失败。

**修复**: 用委托模式解耦——在 `BrowserMcpPlugin.companion` 暴露 `toolExecutor` 委托字段（`@JvmField`），由 `BrowserActivity` 在初始化时通过**反射**注入一个 lambda。`BrowserBridge` 实例化只发生在浏览器模块内部，插件完全不认识它。

### 教训: MCP 插件 + 浏览器 = 单向委托

插件定义接口（`toolExecutor`），浏览器注入实现。这是微内核插件的标准模式：
- 插件只依赖 kernel → 可独立编译
- 宿主模块通过反射注入能力 → 解耦

## 3. 任务边界标记

### 教训: 硬编码中文标记不对

原来任务完成后的边界消息永远是中文 `[上任务结束。新对话。勿重复上文命令。]` ——英文 Agent 看不懂。

**修复**: 根据 `agentLanguage` 选择中英文边界标记。中文版保留了更清晰的"上一任务已结束。以下为新对话。"措辞。

## 4. HTTP 响应体读取超时

### 教训: 别在 catch 里重试同一个操作

`bodyAsText()` 超时后，catch 里又调了一次 `bodyAsText()`——几乎必然再超时。这是无效重试，让超时的调用者多等一倍时间。

**修复**: 直接抛出 `LlmApiException` 带上下文消息（"Body read failed after HTTP 200"），让外层的指数退避重试机制接手。HTTP 200 后读超时是 socket 闲置超时，增加重试次数比同一次调用内重试有效。

## 5. 思考步骤 UI 重构

### 教训: 重构时别丢信息

UI 从旧版（Thought/Action/Observation 各自可折叠）改为新版（Thought 始终可见 + Action/Observation 合并折叠）时：
- 丢失了 **Step 编号**（`Step ${trace.step}`）
- Observation 被嵌套在 `if (trace.action != null)` 里面，如果 action 缺失观察就全丢了

**修复**: 恢复 Step 编号（`Monospace` 10sp 小蓝字）+ 放宽条件（`action != null || observation 非空` 都显示）+ 无 action 时显示 `(observation)` 占位。

---

## 6. Few-Shot 不能太瘦

### 教训: 删掉插件发现示例 = Agent 学不会装插件

原提示词有 3 个示例（状态查询 / 文件操作 / 插件发现），压缩时合并成 1 个（状态+文件）。Agent 就不知道如何发现和安装插件。

**修复**: 恢复为 2 个紧凑示例——示例 1（状态+文件）+ 示例 2（发现插件 → 查详情 → 安装）。
