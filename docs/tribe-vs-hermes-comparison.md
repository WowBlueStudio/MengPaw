# 部落协作 (Tribe) vs Hermes Agent — 超详细对比

> MengPaw 部落协作插件 vs NousResearch Hermes Agent 多智能体协作机制
> 2026-07-27

---

## 一、命名与哲学

| 维度 | Hermes Agent | 部落协作 (Tribe) |
|------|-------------|-----------------|
| 命名来源 | 希腊神话赫尔墨斯（众神信使） | 《魔兽世界》部落（兽人/牛头人/巨魔/亡灵协同作战） |
| 协作隐喻 | 信使传递消息 | 部落成员各司其职、共享战利品（记忆） |
| 设计哲学 | 中心化 Orchestrator + Worker 池 | 去中心化 P2P 文件交换 + ACP 消息 |
| 核心概念 | Command/Request/Notification/Report | 团队 (Team) / 发现 (Discover) / 委派 (Delegate) / 共享记忆 (Memo) |

## 二、协议栈对比

### 2.1 Hermes Agent — ACP 协议

```
┌─────────────────────────────────────────────────┐
│                 Hermes ACP 协议栈                 │
├─────────────────────────────────────────────────┤
│ 消息类型 (4种)                                    │
│  ├─ Command   P0  主→从  必须执行，必须回复        │
│  ├─ Request   P1  对等   期望回复，非强制           │
│  ├─ Notification P2 广播  单向，无需回复            │
│  └─ Report    P1  从→主  结构化状态/结果           │
├─────────────────────────────────────────────────┤
│ 通信模式 (4种)                                    │
│  ├─ 同步 RPC       阻塞等待，低延迟，强一致性       │
│  ├─ 异步消息       高吞吐，解耦，削峰填谷           │
│  ├─ 发布订阅       完全解耦，一对多                 │
│  └─ 共享黑板       共享状态，松耦合，可发现          │
├─────────────────────────────────────────────────┤
│ 上下文优化 (3层)                                   │
│  ├─ 按需裁剪  15000→2000 tokens (87%压缩)         │
│  ├─ 引用传递  ref:// 指针替代内联 (60%压缩)        │
│  └─ 共享去重   100次协作后自动压缩62%               │
├─────────────────────────────────────────────────┤
│ 容错机制                                          │
│  ├─ 指数退避重试 30s→60s→120s (最多3次)           │
│  ├─ 降级策略   本地缓存/默认策略/替代Worker         │
│  └─ 死信队列   失败消息→系统边界检测数据源           │
├─────────────────────────────────────────────────┤
│ 任务编排                                          │
│  ├─ Kanban 看板 状态机驱动                         │
│  ├─ 隔离上下文   子Agent独立会话+终端+工具集         │
│  └─ 嵌套委派     最多3层                           │
└─────────────────────────────────────────────────┘
```

### 2.2 部落协作 — 当前实现

```
┌─────────────────────────────────────────────────┐
│                Tribe 文件协作协议                  │
├─────────────────────────────────────────────────┤
│ 消息类型 (2种，隐式)                               │
│  ├─ 委派任务   写入 inbox/task_<ts>.md            │
│  └─ 共享记忆   写入 TEAM_MEMOS/memo_<ts>.md       │

│ 通信模式 (1种)                                    │
│  └─ 文件轮询   对方 Agent 周期性读 inbox/ 目录     │

│ 上下文优化                                        │
│  └─ 无          全量读写文件                       │
├─────────────────────────────────────────────────┤
│ 容错机制                                          │
│  └─ 无          写失败只上报 ErrorCollector        │
├─────────────────────────────────────────────────┤
│ 任务编排                                          │
│  ├─ 手动委派   Agent 逐个调用 tribe.delegate       │
│  ├─ 无隔离      共享文件系统                       │
│  └─ 无嵌套      不支持链式委派                     │
└─────────────────────────────────────────────────┘
```

## 三、逐功能对比

### 3.1 团队管理

| 功能点 | Hermes Agent | Tribe 当前 | 差距 |
|--------|-------------|-----------|------|
| 成员注册 | Orchestrator 主动发现 + 注册 | 手动 `tribe.team invite` 写文件 | 🔶 |
| 角色定义 | Worker 配置文件定义 role + skills | `Profile.md` 正则提取 | 🔶 |
| 能力路由 | 基于角色+历史性能自动匹配 | 手动指定目标 Agent | 🔴 |
| 在线检测 | ACP Heartbeat 实时心跳 | 无 | 🔴 |
| 权限控制 | Command(P0)强制 / Request(P1)可选 | 无优先级概念 | 🔴 |

### 3.2 任务委派

| 功能点 | Hermes Agent | Tribe 当前 | 差距 |
|--------|-------------|-----------|------|
| 委派方式 | `agent.delegate(task, to=worker)` | `tribe.delegate <name> <task>` | 🟢 |
| 任务队列 | Kanban 看板 + 状态机 | inbox/ 目录文件 | 🔶 |
| 并行执行 | 最多 3 个并行 Worker | 不支持 | 🔴 |
| 结果收集 | Worker 返回 Final summary | 等待对方写 Memory.md | 🔴 |
| 超时处理 | 可配置 timeout + 自动重试 | 无 | 🔴 |
| 嵌套委派 | 最多 3 层 | 不支持 | 🔴 |

### 3.3 共享记忆

| 功能点 | Hermes Agent | Tribe 当前 | 差距 |
|--------|-------------|-----------|------|
| 写入 | Worker 自动写回 context | `tribe.memo <content>` 手动 | 🔶 |
| 读取 | 共享内存去重 + 上下文注入 | `tribe.memo` 无参列出最近 10 条 | 🔶 |
| 压缩 | 100 次协作后自动压缩 62% | 无 | 🔴 |
| 隐私 | 隔离上下文，子 Agent 不可见父上下文 | 全量文件可读 | 🔴 |

### 3.4 通信基础设施

| 功能点 | Hermes Agent | Tribe 当前 | 差距 |
|--------|-------------|-----------|------|
| 传输层 | WebSocket + HTTP | 文件系统（同设备）/ ACP（跨设备） | 🟡 |
| 序列化 | JSON (结构化) | Markdown (半结构化) | 🔶 |
| 加密 | TLS + Token 认证 | ACP AES-256-CBC（跨设备时） | 🟢 |
| 发现 | Orchestrator 主动扫描 | `tribe.discover` 扫描本地目录 | 🔴 |

## 五、演进路线建议

### Phase 1 — 当前 (v0.1.1→v0.2.0)
- ✅ 文件系统协作 (team/discover/delegate/ask/memo/role)
- ✅ ACP 跨设备消息（通过 browser-push 模式）
- 🔜 重命名为 Tribe（部落协作）

### Phase 2 — 短期 (v0.3.0)
- [ ] 引入消息优先级 (P0 必须 / P1 期望 / P2 尽力)
- [ ] inbox 轮询 → ACP 实时推送
- [ ] 委派超时 + 自动重试

### Phase 3 — 中期 (v0.4.0)
- [ ] Kanban 看板状态机
- [ ] Worker 能力路由（基于角色+历史）
- [ ] 子 Agent 上下文隔离

### Phase 4 — 长期 (v1.0.0)
- [ ] 上下文自动裁剪
- [ ] 嵌套委派链
- [ ] 共享记忆去重
