# make-skill vs make_skills 对比分析（2026-08-02）

> 背景：吸收 make-skill（旧技能）优点进 make_skills（我们制作的技能），吸收完成后 make-skill 已删除——技能体系合并为单一 make_skills。

## 对比

| 维度 | make-skill（旧） | make_skills（新） | 优劣 |
|------|-----------------|-------------------|------|
| 触发词 | 「把这个变成 skill」「记住这个流程」「保存为技能」——3 个口语化直接触发词 | 「设计个技能」「做个技能」「把这事做成技能」——偏"新设计"语义 | **旧优**：口语化沉淀触发词更贴近"沉淀当前会话"的即时场景 |
| 适用场景 | 明确"把当前对话中的工作流/排错路径/配置步骤沉淀" | 泛"按需设计" | **旧优**：会话沉淀入口显式 |
| 类型决策 | 无（单一沉淀路径） | 三类选型表（知识剧本/剧本+脚本/Flow） | **新优**：按需求形态决策 |
| 进化目标 | 无 | 树状 vs 线性概念 + 进化目标三要素（目标/稳定锚点/收敛原则） | **新优**：线性进化的方向锚 |
| 进化闭环 | 无 | 失败→对照目标→分类处置→push→mark-corrected→记忆沉淀 | **新优**：技能自进化 |
| 创建路径 | plugin.create --type script 骨架 + agent.write + skill.ls | skill.create + agent.write + skill.ls + skill.push + skill.run 自测 | 持平（skill.create 更对口；make-skill 的 script 骨架实际创建的是 SCRIPT 插件非 skill 文件，属旧瑕疵） |
| 格式模板 | 单模板（frontmatter + 适用场景/执行步骤/注意事项） | 三模板（知识/脚本+脚本执行约定/Flow 检查点+禁止段） | **新优**：按类型给骨架 |
| 示例 | 完整示例（查天气：net.curl wttr.in） | 无 | **旧优**：可执行的最小示例降低学习成本 |
| 剧本完整性 | 65 行 | ~150 行（含概念/选型/闭环） | 新更长但信息密度高；旧更短更易消化 |

## 吸收内容（已合入 make_skills）

1. **触发词补全**：description 增加「把这个变成 skill」「记住这个流程」「保存为技能」「沉淀这个会话」
2. **会话沉淀入口**：开头新增双入口（按需设计 / 会话沉淀），明确"把当前对话中的工作流、排错路径、配置步骤沉淀为技能"
3. **完整示例**：新增查天气示例（沿用 make-skill 的 net.curl wttr.in 流程），并补进化目标三要素示范

## 未吸收（及理由）

- **plugin.create --type script 骨架路径**：探索确认该命令创建的是 SCRIPT 类型插件（无运行时执行引擎），并非 skill 文件——skill.create 是正确路径，不吸收
- **单模板简化**：make_skills 的三类模板是核心价值（类型决策），不回归单模板

## 结果

- make-skill 已删除（assets 母本 + DEFAULT_SKILLS 条目 + 引用排查干净）
- 技能体系 = 单一 make_skills：双入口（设计/沉淀）+ 三类选型 + 进化目标 + 进化闭环 + 示例
